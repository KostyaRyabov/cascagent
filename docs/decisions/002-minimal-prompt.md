# ADR-002: Минимальный промпт (~50 токенов) вместо подробного

- Статус: **Accepted**
- Дата: 2026-10-09
- Расширено в: `docs/prompts.md` §2, `docs/cpu-offload.md` P6/P8

## Контекст

Каждый токен system-префикса оплачивается на каждом вызове (префилл, VRAM).
Малые модели (4-8B) нарушают сложные форматы и путаются в длинных
инструкциях. Итерации: v1 с категориями (~800 токенов) -> v2 с примерами
(~400) -> финальный (~50).

## Решение

System prompt декомposer'а фиксируется дословно (~200 символов, protocol §2,
константа `parser.SYSTEM_PROMPT`). Формат задаётся одной строкой шаблона
«Название / <4 пробела>Описание», без few-shot. Модель не знает ни о чём, кроме
«разбей задачу или напиши `<atom>`».

## Последствия

- (+) Экономия ~75k токенов на 100 вызовах против v1; стабильный префикс —
  идеальная мишень для prefix caching / KV save-restore.
- (+) Промпт почти не влияет на качество — его можно менять редко; тесты
  снапшотят текст.
- (-) Часть ответственности за формат переносится на CPU-парсер: он обязан
  быть толерантным (отступы любого размера, пустые строки, варианты `<atom>`).
- (-) Без примеров модель иногда копирует структуру вопроса — ловится
  DuplicateDetector/degenerate-правилом, не ретраями.
