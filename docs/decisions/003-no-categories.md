# ADR-003: Категории задач удалены из протокола (v1 -> v2)

- Статус: **Accepted**
- Дата: 2026-10-09
- Расширено в: `docs/data.md` §1, `docs/protocol.md` §4, `docs/prompts.md` §6

## Контекст

v1 вводил категории символом: `>` must_do, `!` deferred, `?` research,
`⚛` atom. Наблюдения: малая модель систематически путала символы, ставила
их в начало строки описанием, тратила THINK-токены на выбор категории;
промпт разрастался; acceptance criteria генерировались недетерминированно.

## Решение

Категории удаляются полностью. Модель либо декомпозирует (простой текст),
либо пишет `<atom>`. Всё остальное решает CPU:
- порядок исполнения = порядок siblings в списке (FIFO, cpu-offload A9);
- «research-подобные» задачи определяются enricher'ом по gaps/confidence,
  а не меткой модели;
- deferred нет: очередь одна, приоритет — дерево слева направо;
- атомарность — только точный токен + детерминированное degenerate-правило.

Удалены также поля `acceptance` (входит в description) и `blocked_by`
(выводимо из дерева).

## Последствия

- (+) Модель делает ровно одно семантическое действие; промпт -~750 токенов.
- (+) Нет класса ошибок «неверная категория»; парсер стал тривиальным.
- (-) Потеря явной маркировки приоритетов: если позже понадобится
  «сначала исследование», это решается оркестратором (метка в metadata),
  а не возвращением категорий в промпт.
